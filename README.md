# 达成编写一千万行代码的成就

本项目实现了一个用于判断奇偶数的交互式程序。不过，我们不使用取模这种奇技淫巧，而是一个数一个数地进行匹配。这样的代码手写起来很痛苦，但我们可以借助生成器，从而轻松达成编写一千万行代码的成就。

## 生成代码

想要多少行自己填。下面的示例是一千万行

```sh
node codegen.js 10000000
```

生成器会固定读取 `input.js`，然后将结果写入 `output.js`。

## 运行程序

`output.js` 就是最终要运行的程序

```sh
node output.js
```

输入一个非负整数，程序会告诉你它是不是偶数。数字存在判定范围，最小值为 `0`，最大值就是生成代码时指定的行数。

## 统计代码量

生成代码后运行命令

```sh
tokei --no-ignore --type JavaScript
```

结果如下所示

```txt
===============================================================================
 Language            Files        Lines         Code     Comments       Blanks
===============================================================================
 JavaScript              4     10000133     10000106            4           23
===============================================================================
 Total                   4     10000133     10000106            4           23
===============================================================================
```

## 实现方式

`input.js` 中使用两个注释标记代码在哪里生成

```js
...
/* CODEGEN-BEGIN */
...
/* CODEGEN-END */
...
```

`codegen.js` 首先得到 `/* CODEGEN-BEGIN */` 前和 `/* CODEGEN-END */` 后的内容，然后往 `output.js` 中先写入标记前的内容，再写入生成的代码，最后写入标记后的内容。

为了改善性能，生成的代码不是一行一行地写入，而是一批一批地写入。通过把大量小写入合并为少量大写入，显著地减少了 IO 的次数——这对性能的影响相当可观。

## 性能分析

### 代码生成器的性能

测试环境

| 项目 | 配置 |
| --- | --- |
| OS | WIN32_NT 10.0.26200.9168 |
| CPU | Intel Core i9-13900H 12+8 5.40 GHz |
| Node.js | v24.19.0 |
| hyperfine | v1.20.0 |

使用默认批大小 `4096`，预热 2 次

```sh
hyperfine --warmup 2 "node codegen.js 10000000"
```

10 次测试的统计结果为

```txt
Time (mean ± σ):      1.743 s ± 0.028 s
Range (min … max):    1.689 s … 1.776 s
```

`codegen.js` 的第二个参数用于修改批大小。如果你愿意，可以尝试将其设为 `1`，以感受逐行写入的速度究竟慢到了什么程度

```sh
node codegen.js 10000000 1
```

### 奇偶判断程序的性能

程序初始启动很慢（我猜测是因为要加载大量代码）

输入第一个数字后过很久才产生结果（我猜测是 JIT 的原因）

后续速度就正常了。
